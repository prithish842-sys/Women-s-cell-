# Security Policy

## Reporting a Vulnerability

Please do not publish security vulnerabilities in public GitHub issues.

Report vulnerabilities through the repository owner's private maintainer contact channel. If no private channel is listed, request one without including exploit details or private records in the public issue.

## Sensitive Data

Do not include real student, faculty, ICC complaint, attachment, phone, email, register-number, or production database data in reports.

Use minimal reproduction steps, test-only accounts, redacted screenshots, and synthetic payloads. Include affected routes, expected behavior, observed behavior, and safe steps to reproduce without exposing private records.

## Supported Versions

Security fixes are handled on the default branch unless a maintained release branch is explicitly announced by the project owner.
